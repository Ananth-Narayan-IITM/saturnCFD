Detailed Description

solvers

One directory per PDE. A solver is self-contained: lifecycle, options, state, equations and diagnostics.

Naming convention

Every solver library is named

saturn<SolverName>

Examples:

saturnBurger
saturnHeat
saturnStokes
saturnIncompressible

Implemented solvers are saturnBurger (1D/2D/3D scalar Burgers), saturnHeat (1D/2D/3D scalar convection–diffusion) and saturnStokes (2D/3D steady coupled Stokes with PETSc).

Each solver directory has its own README.md explaining the equations, data layout, algorithm, validation and limitations.

Adding a solver

cp -r src/solvers/saturnBurger src/solvers/saturnMyBurger
# rename the class/target and add one line to src/solvers/CMakeLists.txt:
# addSolver(saturnMyBurger)
# then add its registration call to BuiltinSolvers.cpp

The saturnCFDSolver scaffold tool will automate the copy/rename. Until then the manual copy works. See docs/guides/writingASolver.md.

Boundaries

  • A solver may use mesh, fv, linalg, io and simulation.
  • A solver may not edit them for its own equation.
  • No runtime plugin in v1.0: solvers are static libraries linked into saturnCFD.

saturnStokes

saturnStokes solves

\[-\nabla p + \mu\nabla^2\mathbf{u}=\mathbf{f}, \qquad \nabla\cdot\mathbf{u}=0 \]

with a coupled \(u,v,w,p\) saddle-point matrix and PETSc. The validation core uses the direct coupled solve; the fieldsplit/Schur path is being tuned. Examples are in examples/saturnStokes/. Design: docs/theory/coupledSaddlePoint.md and docs/theory/stokes.md.
