Documentation and formatting pipeline

Status: accepted (ADR 0013).

Goals

  1. One source for API docs, theory pages, protocols, ADRs and validation records.
  2. HTML for browsing and GitHub Pages hosting.
  3. PDF for submission and offline reading.
  4. Equations that render in both Markdown viewers and Doxygen.
  5. clang-format enforced for every C++ file.

Source of truth

docs/ is the documentation source. Doxygen reads:

  • README.md;
  • docs/**/*.md;
  • src/**/*.hpp and src/**/*.cpp once the source exists.

docs/index.md is the Doxygen main page.

Markdown math

Markdown pages use $...$ inline and $$ ... $$ display so they render in GitHub, VS Code, Obsidian and Pandoc.

Doxygen does not parse those delimiters, so the Doxygen build runs a small input filter:

tools/doxygenMathFilter.py

It converts, outside code blocks and inline code:

  • $...$ -> \f$...\f$
  • $$...$$ -> \f[...\f]
  • [@key] -> \cite{key}

The Markdown source stays GitHub-friendly; the filter adapts it for Doxygen. The bibliography is docs/references.bib, wired through CITE_BIB_FILES.

Doxygen

docs/Doxyfile sets:

GENERATE_HTML = YES
GENERATE_LATEX = YES
USE_PDFLATEX = YES
USE_MATHJAX = YES
CITE_BIB_FILES = docs/references.bib
INPUT = README.md docs src
OUTPUT_DIRECTORY= buildCPU/doxygen

CMake targets:

target output
docHtml buildCPU/doxygen/html/index.html
docPdf buildCPU/doxygen/latex/refman.pdf
doc both
formatCode runs clang-format on tracked C++ files

GitHub Pages

.github/workflows/docs.yml:

  • runs on push to v1/main and on workflow_dispatch;
  • installs Doxygen and Graphviz;
  • runs mkdir -p build && doxygen docs/Doxyfile;
  • uploads buildCPU/doxygen/html as the saturnCFD-docs-html artifact;
  • publishes buildCPU/doxygen/html to the gh-pages branch with peaceiris/actions-gh-pages.

The Pages URL is:

https://ananth-narayan-iitm.github.io/saturnCFD/

Manual repository setting (once): Settings -> Pages -> Build and deployment -> Deploy from a branch -> Branch: gh-pages / (root) -> Save. Direct link: https://github.com/Ananth-Narayan-IITM/saturnCFD/settings/pages.

The workflow also needs permission to push the branch: Settings -> Actions -> General -> Workflow permissions -> Read and write permissions. If Pages is not enabled, the site returns 404 even though the branch exists. The HTML is also uploaded as the saturnCFD-docs-html artifact, so the build is not lost.

The workflow does not call actions/configure-pages or actions/deploy-pages. A workflow token cannot create a Pages site (Resource not accessible by integration); branch publishing avoids that admin-only API.

The PDF is built on workflow_dispatch and uploaded as a workflow artifact. It is not rebuilt on every push because the TeX installation is large.

clang-format

  • .clang-format is the single style file.
  • Local command:
    clang-format -i $(git ls-files '*.hpp' '*.cpp')
  • CMake target:
    cmake --build buildCPU --target formatCode
  • .github/workflows/format.yml runs:
    clang-format --dry-run --Werror $(git ls-files '*.hpp' '*.cpp')
  • A change that fails the format check is not merged.

clang-tidy is optional in v1.0; the config file exists, but it is not a blocking check until the source is stable.

Doxygen comments in code

Use \f$...\f$ in C++ comments, $...$ in Markdown. The filter only touches Markdown.

Validation

  • mkdir -p build && doxygen docs/Doxyfile builds HTML without missing-input errors.
  • make -C buildCPU/doxygen/latex produces refman.pdf.
  • The Pages workflow deploys and the URL loads.
  • A $...$ equation appears as an equation in HTML and PDF.
  • clang-format --dry-run --Werror passes on tracked C++ files.
  • The format workflow fails on a deliberately misformatted file.
