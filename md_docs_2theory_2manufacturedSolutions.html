Method of manufactured solutions

Status: required verification method for the FVM layer.

1. What it is

The method of manufactured solutions (MMS) starts by choosing an exact, smooth solution \(\phi(x,y,z,t)\). It is substituted into the continuous PDE to obtain a source term:

\[s = \mathcal{L}(\phi). \]

The discrete solver is then run with that source and the boundary conditions that \(\phi\) satisfies. The numerical solution \(\phi_h\) is compared with the exact \(\phi\) at cell centroids. Refining the mesh gives the observed order of accuracy:

\[p \approx \frac{\log(e_{\mathrm{coarse}}/e_{\mathrm{fine}})}{\log 2}. \]

MMS does not require an exact solution of the discrete system. It tests the implementation of the discrete operator against the continuous one.

2. Why we use it

A unit test checks one function in isolation. A regression test checks that an accepted result did not change. Neither answers this question:

Does the full discrete operator converge to the PDE at the expected order?

MMS does. It catches:

  • a wrong sign or coefficient in a flux;
  • a missing face or a double-counted partition face;
  • a wrong ghost-cell fill or boundary condition;
  • a wrong cell volume or face area;
  • an interpolation that is only first-order where it should be second-order;
  • a halo bug that is invisible on one rank.

It is also the only practical way to verify a new PDE/boundary-condition combination before a physical benchmark exists.

3. Diffusion/Laplacian MMS

For

\[\nabla^2\phi = s, \]

choose a periodic solution on the unit cube:

\[\phi(x,y,z)=\sin(2\pi x)\sin(2\pi y)\sin(2\pi z). \]

Then

\[s = -(2\pi)^2\,d\,\phi, \]

where \(d\) is the number of active dimensions (1, 2 or 3). The same field is periodic in every direction, so the halo/periodic path is exercised without a boundary-condition error.

For a Dirichlet test, choose a non-periodic \(\phi\) and set its exact boundary values. For a Neumann test, choose \(\phi\) whose normal derivative vanishes on the boundary:

\[\phi(x,y,z)=\cos(\pi x)\cos(\pi y)\cos(\pi z). \]

Then \(s=-(d\pi^2)\phi\) and \(\partial_n\phi=0\) on every wall.

4. Advection–diffusion MMS

For

\[\frac{\partial \phi}{\partial t} + \nabla\cdot(\mathbf{a}\phi) = \nu\nabla^2\phi + s, \]

choose a smooth \(\phi(\mathbf{x},t)\) and a known velocity \(\mathbf{a}\), then

\[s = \frac{\partial \phi}{\partial t} + \nabla\cdot(\mathbf{a}\phi) - \nu\nabla^2\phi. \]

Use two tests:

  1. Steady MMS — no time term, solve to a steady state or solve the linear system directly.
  2. One-step MMS — start from \(\phi(\mathbf{x},0)\), take one step and compare with \(\phi(\mathbf{x},\Delta t)\); refine \(\Delta t\) and \(h\).

The second separates spatial error from time-integration error. If both are refined together, the observed order is the minimum of the two.

5. What to measure

For each refinement level \(h, h/2, h/4\):

\[L^1 = \frac{1}{N}\sum_P |\phi_P-\phi(\mathbf{x}_P)|, \quad L^2 = \sqrt{\frac{1}{N}\sum_P (\phi_P-\phi(\mathbf{x}_P))^2}, \quad L^\infty = \max_P |\phi_P-\phi(\mathbf{x}_P)|. \]

Report:

  • the three norms;
  • observed order \(p\) for each norm;
  • the refinement ratio;
  • whether the asymptotic range was reached;
  • CPU/GPU and 1/2-rank parity.

Expected order for the first implementation:

operator expected order
central Laplacian on a uniform hex mesh 2

A TVD limiter can reduce the observed order at smooth extrema. That is a property of the scheme, not necessarily a bug; document it and use a smooth test that avoids the extremum if the goal is the spatial order.

7. Why periodic first

Periodic MMS removes the boundary-condition implementation from the error. If the periodic case is second order, the interior operator and halo exchange are correct. Then Dirichlet and Neumann isolate the boundary ghosts. This is the fastest way to localize a bug.

8. MMS versus other tests

test question
unit test does one function do what it claims?
MMS does the assembled operator converge at the expected order?
regression did an accepted result change?
physical benchmark does the model match reality/reference data?

All four are needed. MMS is not a substitute for a benchmark, and a benchmark is not a substitute for MMS.

9. Common pitfalls

  • Inconsistent source. The source must be evaluated at cell centroids with the same discrete operator; a continuous source sampled at the wrong point produces a first-order error.
  • Boundary values. Dirichlet/Neumann MMS needs the exact boundary data, not zero.
  • Ghost fill order. Halo exchange before physical BC, then MMS comparison after a complete operator application.
  • Mixed refinement. Refining both \(h\) and \(\Delta t\) gives the minimum order; refine them separately when possible.
  • Limiter order. A TVD limiter can clip a smooth extremum; do not call that a convergence bug without checking the limiter branch.
  • Too few refinements. Two refinements can be in the pre-asymptotic range; use three where possible.
  • Roundoff. Float builds have a higher error floor; compare within the precision-dependent tolerance.

10. Acceptance criteria

  • All three norms decrease under refinement.
  • Observed order is within about 0.2 of the expected order in the asymptotic range.
  • The same order is observed on 1, 2 and 4 ranks.
  • CPU/GPU parity is within the precision floor.
  • A deliberately broken sign, coefficient or halo test fails MMS.
