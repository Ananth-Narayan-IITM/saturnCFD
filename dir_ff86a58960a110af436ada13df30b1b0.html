Detailed Description

saturnBurger — 1D scalar Burgers solver

Target: saturnBurger

Class: saturn::SaturnBurger

Registered name: saturnBurger

Equation: 1D scalar Burgers

\[\frac{\partial u}{\partial t} + \frac{\partial}{\partial x}\left(\frac{u^2}{2}\right) = \nu\frac{\partial^2 u}{\partial x^2} + s . \]

This is the first production solver and is fully registered in the CLI: saturnCFD -listSolvers prints saturnBurger, and a case file runs with saturnCFD case.yaml. The 2D/3D extension will keep the saturnBurger name and add the transverse directions.

Why the files are split

  • SaturnBurger.hpp/.cpp is the physics and numerics: mesh partition, fields, Burgers flux, diffusion, boundary refresh, RHS and time state. It does not include Config, YAML or the registry.
  • BurgersCase.hpp/.cpp is the case layer: the YAML schema, mesh choice, burgers.initial presets, the exact traveling-wave helper and the registry entry. It translates a case file into a SaturnBurger.
  • README.md documents both.

This keeps the solver usable from C++ tests without YAML, and keeps YAML and case presets out of the RHS. There are no tests in this directory: all tests are in tests/TestSaturnBurger.cpp, tests/regression/burgers/ and tools/validateBurgers.py. The profile/exactError methods are user-facing CLI diagnostics (output.exact and output.csv), not test code.

BurgersCase is not redundant with SaturnBurger: one is "what case", the other is "how to advance it". If they were merged, the physics class would have to include Config, ConfigSchema, MeshFactory and the registry.

Running the YAML case

cmake --preset default
cmake --build buildCPU -j
./buildCPU/saturnCFD -listSolvers # saturnBurger
./buildCPU/saturnCFD -dumpConfig saturnBurger # full template
./buildCPU/saturnCFD -checkConfig \
tests/regression/burgers/traveling64.yaml
./buildCPU/saturnCFD tests/regression/burgers/traveling64.yaml
mpirun -np 4 ./buildCPU/saturnCFD \
tests/regression/burgers/traveling64.yaml

A standalone user example with an independent analytic check is in examples/saturnBurger/:

cd examples/saturnBurger
saturnCFD saturnBurger.yaml
python3 compareAnalytic.py

It uses 256 cells on \([0,1]\), \(x_0=0.25\) and \(t=0.5\) s and reports \(L^2=4.226\times10^{-5}\) against the exact wave. The script recomputes the analytic solution from the case parameters rather than trusting the solver's u_exact column.

The case writes results/burgers/traveling64.csv and .json when output.csv and output.json are true. The CSV is the raw field at the final time, one row per cell:

x,u_numerical,u_exact,error

The JSON stores wallSeconds, l1/l2/linf of the state and the analytic error. The prefix is relative to the current working directory.

With MPI, the CLI chooses OMP_NUM_THREADS = max(1, cores/ranks) unless it is already set, and passes it explicitly to Kokkos; this avoids oversubscription when several ranks share a node.

Mesh and layout

Requirements:

  • a structured 1D block: mesh.dimension == 1, ny = nz = 1;
  • computeGeometry() and detectStructured() already called;
  • at least two cells per rank when nGrow = 2.

The case factory builds the mesh with makeMeshFromConfig (a structured box or a checked Gmsh mesh), then the solver constructs:

MeshPartition (nx, 1, 1, periodic, false, false)
LocalMesh nGrow = 2
CellField u nGrow = 2
FaceField flux, lapFace
CellField div, lap, grad

The shared FVM layer supplies LocalMesh, FieldHalo, fillBoundaryGhosts, divergence, and laplacian.

Discretisation

Convective flux

Burgers is a scalar conservation law with flux

\[f(u) = \frac{u^2}{2}, \qquad f'(u)=u. \]

burgersFlux in src/fv/Convection.cpp computes the outward normal flux. The canonical face orientation is "lower-coordinate cell on the left, higher-coordinate cell on the right", independent of which cell owns the face. That makes the flux antisymmetric across a shared face, which is required for conservation.

Schemes:

scheme face states flux
Rusanov cell values local Lax–Friedrichs
Muscl MUSCL-reconstructed left/right local Lax–Friedrichs
Upwind cell values Godunov (shock/rarefaction)

The default is Muscl with the van Leer limiter. The MUSCL reconstruction needs two ghost layers; the solver enforces that.

Diffusion

Diffusion uses the shared non-orthogonal corrected laplacian on LocalMesh:

\[\frac{1}{V_P}\sum_f \nu A_f \frac{(\phi_N-\phi_P)-\mathbf{d}\cdot\nabla_t\phi_f}{d_\perp}. \]

For the 1D block this reduces to the three-point stencil. nu = 0 is allowed for the inviscid equation.

Source

BurgersOptions::source is a constant source per unit volume. A spatially varying manufactured source is a later extension.

Time integration

SaturnBurger implements Solver::rhs; Simulation owns the time loop. Implemented schemes are forward Euler, SSPRK2 and SSPRK3. The recommended choice is SSPRK3 with a CFL around 0.3.

TimeControl::stableDt uses

\[\Delta t_{\mathrm{conv}} = \mathrm{CFL}\frac{h_{\min}}{\max|u|}, \qquad \Delta t_{\mathrm{diff}} = \frac{s h_{\min}^2}{2d\nu}. \]

For \(\nu>0\) the diffusive limit can dominate on fine meshes. The explicit diffusion solve is the current implementation; implicit/IMEX diffusion through saturnLinAlg is the next step.

The solver implements setTime, so time-dependent Dirichlet data at a moving exact boundary is refreshed after every RK stage.

Boundary conditions

  • Periodic: BurgersOptions::periodic = true; only FieldHalo.
  • Dirichlet: set dirichlet(x, time, component); the callback is evaluated at the face centroid and the ghost is the mirror 2g - u_P.
  • Neumann: not exposed in the first solver; add it by extending BurgersOptions and fillBoundaryGhosts.

The 1D mesh may still carry ymin/ymax/zmin/zmax patches. The solver loops only the active direction, so those patches are ignored.

Initial condition

BurgersOptions::initial(x) is required and is evaluated at cell centroids. applyInitialConditions fills the host view and refreshes ghosts.

The YAML factory provides three initial states:

burgers.initial initial state boundaries exact reference use
travelingWave \(u_0(x)=\frac{U}{2}[1-\tanh(\frac{U(x-x_0)}{4\nu})]\) time-dependent Dirichlet from the exact solution yes quantitative validation
sine \(u_0(x)=-\sin(\pi x)\) periodic only no inviscid shock, TVD/boundedness
constant \(u_0(x)=v\) (burgers.value) constant Dirichlet (or periodic) no flux/conservation sanity

travelingWave is the default because it is the only preset with a known analytic solution at every time. The other two test qualitative behavior, not pointwise accuracy.

A traveling wave means the profile keeps its shape and moves at constant speed: \(u(x,t)=f(x-Ut)\). For viscous Burgers the tanh profile is an exact solution because nonlinear steepening balances diffusion. It is not a numerical scheme; it is a physical solution used for initial data, boundary data and the error norm reference.

Validation against the analytic solution

The exact viscous traveling wave is

\[u(x,t)=\frac{U}{2}\left[ 1-\tanh\left(\frac{U(x-x_0-Ut/2)}{4\nu}\right)\right], \qquad U=1,\ \nu=0.02. \]

tools/validateBurgers.py runs the real YAML case at several resolutions and rank counts, writes convergence.csv and rankIndependence.csv, and produces

Why this solver first

  • It has an exact viscous solution.
  • It exercises nonlinear convection, limiters, time integration, diffusion, boundary ghosts, conservation and MPI.
  • It is the bridge to Navier–Stokes: same convective and diffusive terms, no pressure or continuity.

Limitations and next steps

  • 1D only; ny and nz must be 1.
  • Constant source only.
  • Explicit diffusion; implicit/IMEX BE/CN/BDF2 waits for the FV Poisson matrix assembler and saturnLinAlg.
  • The shock test is conservative and bounded but does not yet report a pointwise shock-speed order.
  • Neumann boundaries and a spatially varying source are not exposed yet.
  • 2D/3D extensions will add transverse flux components and a vector or direction-dependent Burgers flux (the user asked to keep this phase 1D).

Using the solver as a library

BurgersOptions options;
options.nu = 0.02;
options.periodic = false;
options.convection = ConvectiveScheme::Muscl;
options.limiter = Limiter::VanLeer;
options.initial = [](const Vec3& x) { return exact(x.x, 0); };
options.dirichlet = [](const Vec3& x, Real t, int) {
return exact(x.x, t);
};
options.exact = [](const Vec3& x, Real t) { return exact(x.x, t); };
SaturnBurger solver(std::move(mesh), options);
TimeControl control;
control.tEnd = 0.5;
control.cfl = 0.3;
Simulation simulation(solver, control, TimeScheme::SSPRK3);
const SimulationResult result = simulation.run();
if (solver.hasExact()) {
const ExactError error = solver.exactError(result.final.time);
const std::vector<ProfilePoint> profile = solver.profile(result.final.time);
}
