FVM layer with Kokkos-backed fields

Status: CPU operator slice implemented with ADR 0016 (Kokkos CellField/FaceField, halo adapter, structured LocalMesh, interpolation, gradient, divergence, non-orthogonal Laplacian, Dirichlet/Neumann ghosts, upwind/Rusanov/MUSCL convection, advection–diffusion MMS and a simplified Rhie–Chow flux). The pressure Poisson solve, SIMPLE/PISO and PETSc are next.

This is the plan for the first Kokkos field/FVM increment. It builds directly on the MPI partition/halo layer already implemented.

0. What is implemented now

  • Kokkos 4.7.04 is fetched and pinned by default; SATURN_BACKEND=openmp is the CPU default. A CUDA build uses an installed Kokkos and its nvcc_wrapper.
  • CellField is a ghosted Kokkos view with ncomp components.
  • FaceField stores the six face values of each owned cell for the temporary interpolation/divergence workspace.
  • FieldHalo performs device pack, host mirror, MPI Isend/Irecv, device unpack, and local periodic copies. Buffers are allocated once.
  • LocalMesh extracts structured cell/face geometry and boundary patch tags from the global hex mesh into device views with host mirrors.
  • fillBoundaryGhosts fills physical Dirichlet/Neumann ghosts after the periodic/partition halo.
  • interpolate, gradient and divergence are implemented for the cell-local face representation.
  • laplacian on LocalMesh includes the non-orthogonal correction and is exact for a linear field on a sheared mesh; CartesianGeometry remains the simpler uniform-block operator.
  • faceNormalVelocity and convectiveFlux implement upwind, Rusanov and MUSCL (minmod, van Leer, superbee) face fluxes. For scalar advection the Rusanov flux is algebraically upwind.
  • rhieChowFlux implements the simplified face-normal correction average(u).n + c[(p_N-p_P)/d_perp - grad(p)_f.n]; the coefficient is caller-supplied until the momentum diagonal exists.
  • Periodic 2D and 3D manufactured Laplacian tests pass on 1, 2 and 4 ranks with observed order 2.00 (within 0.03 at the finest level).
  • Upwind convection and steady advection–diffusion MMS are first order in 3D.
  • MUSCL L2 order is about 1.6 for minmod/van Leer and 1.15–1.42 for superbee; the reduction from 2 is the expected TVD clipping at smooth extrema.
  • A periodic step advection test stays within the initial bounds.
  • The discrete divergence theorem holds on a sheared mesh.
  • Periodic gradient/divergence MMS on LocalMesh passes on 1, 2 and 4 ranks with observed order about 1.97 and 1.99 for the two refinement pairs.
  • GPU-labelled tests are compiled and run in a CUDA build; the local machine has the GPU but no CUDA toolkit, so that build is not yet verified here.

1. Goal

Replace the host std::vector halo test field with a real ghosted CellField/FaceField backed by Kokkos, and write the first FVM operators against it.

The same source must build and run as:

  • CPU MPI: OpenMP/Serial Kokkos, mpirun -np N;
  • GPU MPI: CUDA Kokkos, one rank per GPU;
  • one GPU now: mpirun -np 1 for performance, -np 2 only for correctness.

2. Build model: CPU and GPU are separate builds

CMake fixes the compiler and backend at configure time. CPU and GPU must be different build directories:

cmake --preset cpu # buildCPU, OpenMP
cmake --build --preset cpu -j
cmake --install buildCPU --prefix "$HOME/.local"
cmake --preset gpu # buildGPU, CUDA
cmake --build --preset gpu -j
cmake --install buildGPU --prefix "$HOME/.local"

The installed saturnCFD carries the backend it was compiled with. Install the CPU or GPU build last to choose which one runs. The run command is always:

mpirun -np 4 saturnCFD case.yaml
mpirun -np 1 saturnCFD case.yaml

Cache variables:

SATURN_BACKEND=openmp|serial|cuda|hip CPU default: openmp
SATURN_ENABLE_KOKKOS=ON default
SATURN_USE_SYSTEM_KOKKOS=OFF CPU default: fetch 4.7.04
SATURN_ENABLE_MPI=ON default
SATURN_PRECISION=double float is not wired yet

The CPU build fetches a pinned Kokkos tag. The GPU build uses an installed, CUDA-enabled Kokkos because CMAKE_CXX_COMPILER must be Kokkos' nvcc_wrapper before the project is configured:

export KOKKOS_ROOT=/path/to/cuda-kokkos
cmake --preset gpu

The installed Kokkos must be built for the target architecture (for example PASCAL61 for the Quadro P620).

Doubles are used everywhere for now, including the GPU. Float CUDA is a later optimisation; Accum must remain double for reductions when it lands.

mpirun is not CPU-only: it launches MPI ranks. The backend compiled into each rank decides CPU vs GPU. One rank per GPU is the performance model.

3. Field layout

CellField<Real>:

class CellField {
public:
using view_type =
Kokkos::View<Real****, Kokkos::LayoutLeft, memory_space>;
KOKKOS_INLINE_FUNCTION
Real& operator()(int i, int j, int k, int c = 0) const;
private:
view_type mData;
int mNGrow, mNcomp;
int mOrigin[3], mExtent[3];
};

A four-dimensional view with extents (nxg, nyg, nzg, ncomp) and LayoutLeft has exactly the flat layout used by the host halo path, so no transpose is needed between the Kokkos and MPI buffers.

Storage is local and ghosted:

nxg = nx + 2*nGrow
nyg = ny + 2*nGrow
nzg = nz + 2*nGrow
sc = nxg*nyg*nzg
index = c*sc + kk*sz + jj*sy + ii

Global indices are passed to operator(); the field subtracts (i0 - nGrow, j0 - nGrow, k0 - nGrow).

VectorCellField is a three-component CellField or a small wrapper around one. It is not a separate memory layout.

FaceField is implemented as temporary cell-local storage: (i,j,k,dir,c) is the face of cell (i,j,k) in direction dir. An internal face is stored from both sides, which is exactly what the cell-centred Gauss loops need. A persistent face-flux field with unique ownership comes with pressure correction.

4. Local geometry on device

LocalMesh is implemented for structured hexahedral meshes. It extracts, for every owned cell:

  • cell volume and centroid (3 components);
  • outward face area, unit normal and centroid for each of the six faces;
  • owner-centroid to face-centroid normal distance;
  • boundary patch index, or -1 for an internal face.

Geometry lives in Kokkos views and is copied once before the time loop. Host mirrors are aliases on a CPU build, so the boundary fill does not duplicate memory there.

CartesianGeometry remains as the simpler uniform-block geometry used by the periodic Laplacian MMS.

Remaining for general meshes:

  • non-orthogonal interpolation and Laplacian correction;
  • local point coordinates for higher-order reconstruction;
  • production path: rank 0 read + scatter instead of each rank reading the global mesh.

5. Halo adapter

The Kokkos path is FieldHalo, not a method on HaloExchange, so comm stays backend-agnostic:

FieldHalo(const HaloExchange& halo, int ncomp);
void execute(CellField& field);
  • HaloExchange still builds the 26-direction op list and owns the host path.
  • FieldHalo owns per-op device and host buffers, allocated once.
  • pack kernel writes a contiguous device View<Real*>;
  • deep_copy to host mirror;
  • MPI_Isend/Irecv;
  • deep_copy back;
  • unpack kernel.
  • Local periodic images are copied device-to-device, also on one rank.

Kokkos::fence() separates pack/unpack from the host copy.

The existing host execute(Real*) remains for tests and CPU fallback. The pack/unpack operation and the 26-direction op list are shared.

6. Kernels

Use Kokkos::MDRangePolicy or a flat range over owned cells. Start with MDRange for clarity; benchmark flat range later.

Rules:

  • loop over owned cells/faces only;
  • read ghost values, write owned values;
  • never capture this in a lambda; pass fields and geometry by value;
  • no allocation inside a kernel;
  • no MPI call in a kernel.

7a. Manufactured-solution methodology

MMS is the primary verification method for this layer, not an afterthought. The full derivation and pitfalls are in ../theory/manufacturedSolutions.md.

The first MMS cases are:

  1. 2D/3D periodic Laplacian — implemented and passing.

    \[ \phi=\sin(2\pi x)\sin(2\pi y)\,[\sin(2\pi z)], \quad s=-d(2\pi)^2\phi. \]

    Run on 1, 2 and 4 ranks. Expected order: 2. Observed on the CPU OpenMP build: 3D 1.978, 1.994; 2D 1.994, 1.999 for the two refinement pairs.
  2. Dirichlet Laplacian with exact boundary values; verifies boundary ghosts. Next.
  3. Neumann Laplacian with \(\phi=\cos(\pi x)\cos(\pi y)[\cos(\pi z)]\); verifies zero-normal-gradient ghosts. Next.
  4. Steady advection–diffusion with a smooth manufactured field — implemented and passing. Upwind order about 0.96 and 0.99 for the two refinement pairs; the residual uses the LocalMesh Laplacian and the convective flux divergence.
  5. MUSCL advection — implemented and passing. L2 order about 1.6 for minmod/van Leer and 1.15–1.42 for superbee, with the expected TVD clipping at extrema. A periodic step test checks boundedness.
  6. One-step transient advection–diffusion; refines \(h\) and \(\Delta t\) separately to separate spatial and temporal order. Next.
  7. CPU/GPU parity and 1-rank/2-rank parity on the same MMS case.

For every case record \(L^1\), \(L^2\), \(L^\infty\), observed order, rank count, backend and precision. A test passes only when the order is in the asymptotic range and matches the expected order within about 0.2.

Why MMS, not just a benchmark: a physical benchmark cannot tell whether a second-order scheme is actually second order, and a unit test cannot catch a halo or face-orientation bug in the assembled operator. MMS tests the assembled discrete operator against the continuous PDE.
