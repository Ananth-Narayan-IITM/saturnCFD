saturnCFD v1

A rewrite of saturnCFD as a structured hexahedral finite-volume solver: scalar transport (Burgers, heat), Stokes and incompressible Navier–Stokes, driven by YAML and validated against analytic solutions.

Status: Phase 1 in progress. Mesh reading, checkMesh, the SI-only validator, yaml-cpp schema validation, CLI help, VTK mesh export, the MPI partition/halo substrate, Kokkos CellField/FaceField, the device halo adapter, structured LocalMesh, interpolation/gradient/divergence, non-orthogonal Laplacian, Dirichlet/Neumann ghost fill, upwind/Rusanov/MUSCL convection, advection–diffusion and divergence-theorem tests, a simplified Rhie–Chow flux, the explicit solver/time loop (forward Euler, SSPRK2/3, diagnostics, registry), and the registered 1D saturnBurger solver are in place. PETSc 3.19.6 is linked through the separate saturnLinAlg library; the 1D/3D Poisson and all-Neumann tests pass on 1/2/4 ranks. The 2D/3D Burgers extension, implicit time schemes, heat solver and FV Poisson matrix assembler are next.

The 1D Burgers solver is validated against the exact viscous traveling wave: \(L^2\) falls from \(9.0\times10^{-3}\) at \(N=32\) to \(7.3\times10^{-6}\) at \(N=1024\) with observed orders 1.98/2.11/2.10/2.06/2.03, and 1/2/4 ranks give identical norms. See docs/validation/burgers.md and the figure docs/validation/figures/burgersValidation.png.

A standalone user example is in examples/saturnBurger/:

cd examples/saturnBurger
saturnCFD saturnBurger.yaml
python3 compareAnalytic.py # independent analytic check + plot

MPI and GPU are first-class from the first FVM layer, not a later port. The decomposition, ghost-cell and one-GPU benchmark plan is in docs/plan/mpiGpuDesign.md.

The validated v0 implementation is preserved on v0-archive (tag v0.3.0) and is a reference for validation data and algorithms, not a tree to copy.

Host requirements

Check the host before a clean build:

python3 tools/checkRequirements.py
python3 tools/checkRequirements.py --install # apt packages when missing
cmake --build buildCPU --target doctor # same check through CMake

requirements.toml lists core, docs, editor and GPU tools with minimum versions. Kokkos, yaml-cpp and doctest are fetched and compiled by CMake. Details: docs/guides/requirements.md.

Build and test

cmake --preset default
cmake --build --preset default -j
ctest --preset regression # the common case
ctest --preset mpi # 1/2/4-rank halo and FVM tests
ctest --preset fv # fields, operators, MMS, Burgers
ctest --preset burgers # YAML Burgers validation on 1/2/4 ranks
ctest --preset petsc # PETSc Poisson/nullspace on 1/2/4 ranks
ctest --preset default # all tests, output on failure

Equivalent without presets:

cmake -S . -B buildCPU -DCMAKE_BUILD_TYPE=Release
cmake --build buildCPU -j
ctest --test-dir buildCPU --output-on-failure

Install the binary so the command is simply saturnCFD:

cmake --install buildCPU --prefix "$HOME/.local"
# ~/.local/bin must be on PATH

yaml-cpp, doctest and Kokkos are fetched automatically when not installed. Kokkos is pinned to 4.7.04 and uses SATURN_BACKEND=openmp by default. SATURN_ENABLE_MPI=ON is the default: it links MPI, defines SATURN_USE_MPI, and builds the MPI partition/halo and FVM tests. The app is still a serial mesh/config front end; the FVM operators live in testSaturnFV. Use -DSATURN_ENABLE_MPI=OFF for a serial build.

PETSc 3.19.6 is enabled in the CPU/default preset and linked through saturnLinAlg. Debian's PETSc is found through pkg-config when find_package(PETSc) fails. Use -DSATURN_ENABLE_PETSC=OFF for a minimal mesh/config build. Setup and solver choices are in docs/guides/petsc.md.

Library targets are uniformly camelCase:

saturnCore mesh, config, comm, FVM
saturnLinAlg PETSc wrappers and matrix assembly
saturnSimulation Solver, registry, TimeControl, explicit time loop
saturnBurger 1D scalar Burgers solver

For clangd, the standard database is buildCPU/compile_commands.json (or buildGPU/compile_commands.json). Link it at the repository root with:

cmake --build buildCPU --target compileDb

See saturnCFD -help clangd and docs/guides/commands.md.

CPU and GPU are separate build directories. The GPU build needs an installed, CUDA-enabled Kokkos because Kokkos' nvcc_wrapper must be the C++ compiler at configure time:

export KOKKOS_ROOT=/path/to/cuda-kokkos
cmake --preset gpu
cmake --build --preset gpu -j
ctest --preset gpu

Build the installed Kokkos for the target architecture (for example PASCAL61 for the Quadro P620). This machine has the GPU but no CUDA toolkit, so the CUDA build is written but not yet run locally.

saturnCFD -version
saturnCFD -listSolvers
saturnCFD -checkMesh tests/data/meshes/box2x2x2.msh
saturnCFD -checkMesh tests/data/meshes/box2x2x2.msh -report results/mesh
saturnCFD -checkMesh tests/data/meshes/box2x2x2.msh -writeVTK results/mesh
saturnCFD -dumpConfig common -writeTemplate common
saturnCFD -checkConfig common.yaml
saturnCFD -help checkMesh
saturnCFD -help build
saturnCFD -help mpi
saturnCFD -help gpu
saturnCFD -help clean
saturnCFD -help test

CMAKE_BUILD_TYPE=Release is an optimised, no-debug-symbols build. The compilation database is buildCPU/compile_commands.json. Clean with cmake --build buildCPU --target clean or by removing the build directory.

Enable completion once per shell:

source <(saturnCFD -completion bash) # bash
source <(saturnCFD -completion zsh) # zsh
saturnCFD -completion fish | source # fish

After that, saturnCFD -dump<Tab> completes -dumpConfig, and saturnCFD -checkMesh tests/<Tab> completes files and directories.

Accepted so far:

  • structured hexahedral Gmsh .msh only; 2D is a one-cell-thick 3D mesh;
  • checkMesh validates topology, structuredness, dimension and quality;
  • collocated cell-centred variables, Rhie–Chow, SIMPLE/PISO;
  • PETSc for all linear algebra; no home-grown Krylov solver;
  • separate solver modules for Burgers, heat, Stokes and incompressible flow;
  • YAML schema generated from solver code, parsed with yaml-cpp 0.8;
  • SI only in v1.0; non-SI YAML input is a validation error;
  • single-dash CLI, -help, -checkMesh (default .vtu + .json), optional -writeVTK patches, generated templates with -dumpConfig -writeTemplate, shell completion;
  • user-editable solvers: copy a solver directory, edit equations, rebuild;
  • no AMR in v1.0; AMR/two-phase is a later milestone.

Command line

saturnCFD case.yaml
saturnCFD -checkMesh mesh.msh
saturnCFD -checkMesh mesh.msh -report results/mesh
saturnCFD -checkMesh mesh.msh -writeVTK results/mesh
saturnCFD -checkConfig case.yaml
saturnCFD -dumpConfig common
saturnCFD -dumpConfig common -writeTemplate common
saturnCFD -help
saturnCFD -help checkMesh
saturnCFD -completion bash

-checkMesh always writes <prefix>.vtu and <prefix>.json. The default prefix is results/<mesh-stem>; -report results/mesh writes results/mesh.json (the extension is optional). -writeVTK additionally writes one boundary .vtp per patch and a .pvd; open the .pvd in ParaView. The full option list is in docs/protocols/cli.md.

Writing a solver

saturnCFDSolver and the built-in burgers directory arrive in Phase 2. The naming and the addSolver(name) build path are fixed now.

saturnCFDSolver burgers myBurgers
# add: addSolver(myBurgers) to src/solvers/CMakeLists.txt
# edit src/solvers/myBurgers/createFields.cpp and equations.cpp
cmake -S . -B buildCPU
cmake --build buildCPU -j
saturnCFD -listSolvers
saturnCFD -dumpConfig myBurgers -writeTemplate myBurgers.yaml

The solver directory is self-contained; the mesh, finite-volume, PETSc and I/O layers are not edited. See docs/guides/writingASolver.md and ADR 0011.
