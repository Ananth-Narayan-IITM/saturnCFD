Detailed Description

v1 protocols

A protocol is a stable contract between two parts of the code. It says what is guaranteed, not how it is implemented. Protocols are written before physics so that the same substrate can carry Burgers, heat, Stokes and incompressible flow without being rewritten for each one.

Rules for every protocol

  1. Purpose and vocabulary.
  2. Interface (C++ signatures, concepts or abstract classes).
  3. Invariants checked by tests.
  4. Ownership and lifetime.
  5. Host/device rules.
  6. Error behaviour.
  7. Parallel behaviour (local/global, rank ownership).
  8. Tests.
  9. References.

Non-negotiable rules

  • No physics in a protocol.
  • No hidden allocation or host/device copy in a hot path.
  • No #ifdef for physics. Backend and dimension switches are the only compile-time branches allowed in the substrate.
  • Every public function is camelCase and documented; every numerical choice cites a reference.
  • No code from GPL projects. Basilisk, NekRS and Nektar++ are read for methodology only.
