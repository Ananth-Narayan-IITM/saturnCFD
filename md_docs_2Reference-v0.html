v1 is not a continuation of v0's structured AMR substrate. v1 uses a structured hexahedral finite-volume mesh read from .msh, collocated cell-centred variables and PETSc. Use v0 as a source of ideas, algorithms and validation data, not as a tree to copy.

Known v0 issues — do not carry forward

  1. Halo ghost-count mismatch. mPressure has 1 ghost, but the cavity's HaloExchange is built with 2. Single-box, non-periodic runs hide it.
  2. Periodic boundaries can be overwritten by fillBoundaryGhosts, which does not skip periodic dimensions.
  3. The cavity is square-only. CavitySolver uses nCells(0) for both directions while the driver accepts an independent domain.ny.
  4. localSum is serial inside a box. It reduces over boxes, not cells.
  5. Allocations inside the time loop. Three MultiFabs per Poisson solve, plus a boxArrays() view per vector operation.
  6. The Poisson result is ignored. An unconverged pressure solve is silent.
  7. Float tolerance is silently clamped to 100*epsilon.
  8. localMin/localMax include ghosts, unlike localSum.
  9. MPI is compiled but not driven. The driver and solver hardcode rank 0.
  10. Version/doc drift. CMake 0.3.0, main.cpp 0.2.0, README v0.2, Scope still describing a collocated scheme.

What v1 should take from v0

  • the validation discipline: analytic solutions, manufactured solutions, regression tables, observed order;
  • the Ghia cavity data and the lessons about checkerboard modes and explicit diffusion limits;
  • the TVD limiter implementation as a reference;
  • the self-registering configuration idea, upgraded to a typed schema;
  • the GPU portability lessons: functor storage, no this in device lambdas, no host access to device memory;
  • the fenced Timer.

What v1 must not take from v0

  • the structured AMR BoxArray/MultiFab data model;
  • the single-box, rank-0 solver assumptions;
  • the home-grown CG solver;
  • the per-solve allocations and serial reductions;
  • the mixed-component staggered storage.
