# saturnCFD

Finite-volume incompressible CFD with block-structured AMR, performance portable
via Kokkos.

**Status: v0.2.** Single-phase incompressible solver validated on the
lid-driven cavity. AMR and multiphase are roadmapped, not implemented.

## Quick start

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/usr/local
cmake --build build -j
ctest --test-dir build --output-on-failure

./build/saturnCFD examples/cavity/demo.yaml     # ~10 s smoke test
./build/saturnCFD examples/cavity/re1000.yaml   # Re = 1000 benchmark
```

Full instructions — including MPI, CUDA, ParaView and troubleshooting — are in
**[docs/Usage.md](docs/Usage.md)**.

## One solver, many cases

The binary is driven entirely by a YAML case file. Nothing is compiled in.

```yaml
solver: cavity          # which physics

domain:
  nx: 128
  ny: 128

flow:
  reynolds: 1000
  scheme: minmod

output:
  prefix: results/cavity/re1000
  vtkEvery: 1000
```

```bash
./build/saturnCFD --list-solvers          # available solvers
./build/saturnCFD --dump-config cavity    # every option, with defaults
```

`--dump-config` is generated by calling the same option readers that parse a
real case file, so it can never drift from the code.

## Design in one paragraph

A level is a set of disjoint rectangular patches (`BoxArray`) distributed over
MPI ranks. Field data lives in `MultiFab`: one flat `Kokkos::View` per rank
holding only its own patches, with a per-patch offset table. Kernels iterate
patches as Kokkos teams, so access patterns stay regular and coalesced — this is
what makes AMR viable on a GPU. Ghost cells are filled by `HaloExchange`, which
resolves every patch-to-patch dependency (including periodic images, edges and
corners) on the host once, then launches one kernel for local copies and one
packed MPI exchange per peer.

The flow solver uses a **staggered (MAC) grid** with a projection method, for
the reasons explained in [docs/Solver.md](docs/Solver.md).

## Validation

Lid-driven cavity, Re = 100, 64², steady state, u along `x = 0.5` versus
Ghia et al. (1982):

| scheme | RMS deviation | max deviation |
|---|---:|---:|
| first-order upwind | 0.00527 | 0.00979 |
| minmod (default) | **0.00200** | **0.00468** |
| van Leer | 0.00234 | 0.00517 |
| MC | 0.00241 | 0.00527 |
| superbee | 0.00322 | 0.00605 |

Higher-order convection with a TVD limiter gives a 2.6× error reduction over
first-order upwind. Details and caveats: [docs/Solver.md](docs/Solver.md).

## Known limitations

These are honest and current:

- **The pressure solve uses conjugate gradients, not multigrid.** CG iterations
  grow as `O(1/h)`, so total work grows as `O(N^1.5)` in 2D. This blocks any
  time-to-solution claim and makes Re = 10000 impractical. Multigrid is the
  next milestone.
- **Single box, single rank.** The MPI halo exchange works and is tested for the
  substrate, but `CavitySolver` assumes one patch on rank 0.
- **Explicit diffusion** imposes `dt < h²/(4ν)`.
- **No AMR yet** — the data structures exist, the hierarchy is not built.
- **Pressure is not written to VTK.**
- **First-order in time** (explicit Euler).
