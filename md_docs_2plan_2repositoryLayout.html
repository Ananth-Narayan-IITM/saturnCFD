Module READMEs

Every module directory has a README.md stating:

  • its responsibilities;
  • its boundaries (what it must not do);
  • its tests;
  • the ADR/protocol/theory pages it implements.

That keeps the first question — "where does this belong?" — answerable without reading the build.

Naming

  • New case and test files use camelCase: traveling64.yaml, burgersTemplate.yaml, meshReport.json.
  • Avoid hyphens and underscores in new case/test names.
  • C++ functions camelCase; types PascalCase; members mPascalCase; constants kPascalCase.
  • CMake helper functions are camelCase: addSolver(forcedBurgers).
  • Tool executables are one word or camelCase: saturnCFD, saturnCFDSolver.
  • Standard names (CMakeLists.txt, README.md, .clang-format) and ADR number prefixes are exceptions.

Solver directories

src/solvers/saturnBurger/
CMakeLists.txt
SaturnBurger.hpp # options + class
SaturnBurger.cpp # geometry, BCs, RHS
README.md # equations, algorithm, validation

A user copies src/solvers/saturnBurger to src/solvers/saturnMyBurger, renames the class/target, and adds one line to src/solvers/CMakeLists.txt:

add_subdirectory(saturnMyBurger)

Each solver target is saturn<SolverName>. saturnCFDSolver saturnBurger saturnMyBurger will perform the copy/rename when the scaffold tool lands; until then the manual copy works.

Tests

  • tests/regression/burgers/traveling64.yaml — case.
  • tests/checkBurgers.cmake — runs the CLI and checks the analytic norms, CSV rows and JSON summary.
  • Unit tests live beside the category they test, not in one giant file.
  • CTest labels: [unit], [mesh], [config], [mms], [regression], [parity], [performance].

Docs

  • docs/Doxyfile is the single Doxygen configuration.
  • docs/index.md is the main page.
  • docs/decisions is the ADR log.
  • docs/protocols is the contract layer.
  • docs/theory is the equation and validation record.
  • docs/guides is user-facing procedure.
  • docs/validation is the measured results.
  • docs/plan is planning, including this page.

Dependencies

  • Kokkos — CPU/GPU portability.
  • MPI — decomposition and halo exchange.
  • PETSc — MPI linear algebra.
  • yaml-cpp 0.8.x — YAML parsing.
  • doctest — tests.
  • Doxygen + LaTeX — HTML and PDF docs.
  • clang-format — formatting.

Dependency acquisition is pinned by cmake/SaturnDependencies.cmake. No hand-written YAML parser and no Bash-only tooling.
