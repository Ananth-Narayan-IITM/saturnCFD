# saturnBurger standalone example

This is a self-contained 1D Burgers example. It runs the registered
`saturnBurger` solver and compares the result with the analytic traveling wave
**independently** of the solver's own exact-solution column.

## Case

$$
\frac{\partial u}{\partial t}
+ \frac{\partial}{\partial x}\left(\frac{u^2}{2}\right)
= \nu\frac{\partial^2 u}{\partial x^2},
\qquad
u(x,t)=\frac{U}{2}\left[
1-\tanh\left(\frac{U(x-x_0-Ut/2)}{4\nu}\right)\right].
$$

| parameter | value |
|---|---|
| domain | $x\in[0,1]$ m |
| cells | `nx = 256`, `ny = nz = 1` |
| viscosity | $\nu = 0.02$ m²/s |
| wave speed | $U = 1$ m/s |
| initial centre | $x_0 = 0.25$ m |
| end time | $t = 0.5$ s (centre reaches $x=0.5$) |
| convection | MUSCL, van Leer limiter |
| time scheme | SSPRK3, CFL 0.3 |
| boundaries | Dirichlet, exact traveling-wave data |

At $t=0.5$ the wave is fully inside the domain, away from both boundaries, so
the comparison is clean.

## Run

From this directory:

```bash
saturnCFD saturnBurger.yaml
python3 compareAnalytic.py
```

`compareAnalytic.py` runs the case itself by default, so this also works:

```bash
python3 compareAnalytic.py
```

Options:

```bash
python3 compareAnalytic.py --cli /path/to/saturnCFD
python3 compareAnalytic.py --no-run          # reuse the existing CSV
python3 compareAnalytic.py --tolerance 1e-4
```

## Expected result

CPU build, 256 cells, $t=0.5$ s:

```text
L1 error    : 2.421051e-05
L2 error    : 4.225856e-05
Linf error  : 1.362376e-04
max |u_exact column - independent analytic| : 0.000e+00
PASS: L2 4.225856e-05 <= tolerance 1.0e-04
```

The zero in the fourth line means the solver's `u_exact` column and the
script's independently recomputed $\tanh$ solution are identical.

The script writes:

```text
results/saturnBurger/comparison.png
results/saturnBurger/comparison.pdf
```

and also reads:

```text
results/saturnBurger/traveling.csv
results/saturnBurger/traveling.json
```

## What was wrong with the first run

The first case was generated by `-dumpConfig saturnBurger`, which uses a
one-cell default mesh (`nx: 1`). With one cell the traveling wave cannot be
represented, and `output.exact: false` meant no analytic comparison was
printed. The result `l1 = l2 = linf = 0.7265` was simply the single cell value.

This example sets `nx: 256`, `output.csv: true` and `output.exact: true`.
The `OMP_PROC_BIND` warning is handled by the CLI, which now sets
`OMP_PROC_BIND=spread` and `OMP_PLACES=threads` before Kokkos starts unless the
user already set them.
