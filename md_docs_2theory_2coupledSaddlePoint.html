Coupled saddle-point solver

Status: design accepted for saturnStokes; the same block is the pressure–velocity core of saturnIncompressible.

1. Why a coupled solve

Steady Stokes flow is linear:

\[-\mu\nabla^2\mathbf{u}+\nabla p=\mathbf{f}, \qquad \nabla\cdot\mathbf{u}=0 . \]

The pressure is a Lagrange multiplier for continuity, so velocity and pressure must be solved together. A segregated method such as SIMPLE or SIMPLEC adds an outer pressure-correction iteration and under-relaxation. For Stokes those iterations are unnecessary: one coupled linear solve gives both fields.

The coupled method also gives the reusable foundation for incompressible Navier–Stokes, where the same saddle-point block appears inside a Picard, Newton or time-step iteration. SIMPLE/SIMPLEC remain useful alternatives for steady Navier–Stokes, but they are not the primary Stokes method.

2. Block system

After discretisation the unknowns are the cell-centred velocity \(\mathbf{u}_h\) and pressure \(p_h\). The linear system is

\[\left[\begin{array}{cc} A & B^{T}\\ B & 0 \end{array}\right] \left[\begin{array}{cc} \mathbf{u}_h\\ p_h \end{array}\right] = \left[\begin{array}{cc} \mathbf{f}_h\\ \mathbf{g}_h \end{array}\right], \]

where

  • \(A\) is the vector viscous operator, with Dirichlet wall rows;
  • \(B\) is the discrete divergence;
  • \(B^{T}\) is the discrete pressure gradient;
  • \(\mathbf{f}_h\) contains body forces and boundary data;
  • \(\mathbf{g}_h\) is the target continuity residual (zero for an incompressible case).

The matrix is symmetric indefinite. For an all-Neumann pressure boundary the constant pressure mode is in the null space; the solver must attach that mode and either fix a reference value or keep the null space.

3. Collocated finite-volume discretisation

The first implementation keeps the existing cell-centred fields:

  • \(\mathbf{u}_P\) and \(p_P\) live at cell centres;
  • momentum rows use the component-wise Laplacian on LocalMesh;
  • the pressure gradient is the cell-centred Gauss gradient;
  • the continuity row uses the centred divergence plus a Brezzi–Pitkäranta pressure Laplacian:

    \[ \nabla\cdot\mathbf{u} - \beta\nabla^2 p = 0, \qquad \beta = \mathrm{stabilization}\,\frac{h_{\min}^2}{\mu}. \]

The pressure Laplacian removes the odd–even pressure mode of a collocated grid and gives the Schur complement a well-defined pressure block. The resulting discrete system is a stabilised saddle-point system: its continuity block is not exactly \(B\) of the continuous problem, but its pressure null space and the velocity/pressure block structure are retained. Every row is assembled per unit volume, so the discrete gradient is the negative transpose of the discrete divergence and the pressure is physical.

Boundary conditions:

  • no-slip and moving walls: Dirichlet velocity rows;
  • inlet: fixed velocity profile;
  • outlet: fixed pressure or zero-gradient velocity;
  • periodic patches: wrapped neighbours;
  • all-Neumann pressure: constant null space, mean pressure reported.

4. PETSc linear solver

The production path is PETSc, not a home-grown Krylov method. The current saturnStokes validation core uses PETSc's coupled direct LU (preonly + lu); the fieldsplit/Schur path below is implemented as an option and is still being tuned for refined meshes.

Matrix and vectors

  • MPIAIJ matrix created by DMCreateMatrix on the DMDA; entries are inserted with MatSetValuesStencil using global logical (i,j,k,c) indices. Building PETSc ids from i + nx*(j + ny*k) is only valid when the DMDA is split along x.
  • Four degrees of freedom per cell in 3D (u, v, w, p), three in 2D.
  • Every equation is assembled per unit volume. This makes the discrete gradient the negative transpose of the discrete divergence, keeps the pressure physical, and scales the Schur complement as 1/mu rather than 1/(mu h^3).
  • The pressure block reuses the scalar Laplacian sparsity pattern; the stabilisation coefficient is beta/h^2 with beta = stabilization * h_min^2 / mu.
  • The fieldsplit index sets are built from the matrix block ownership range, not from the natural cell ordering.
  • Matrix and preconditioner setup are reused when the coefficients do not change. For Navier–Stokes the matrix is rebuilt or updated each outer iteration.

Outer Krylov method

Use GMRES (or FGMRES when the preconditioner is variable) on the coupled system. The outer tolerance is set explicitly, never left at the PETSc default in a validation run. Record the iteration count, preconditioned residual and true residual.

Fieldsplit / Schur preconditioner

The pressure–velocity block is solved with PETSc PCFIELDSPLIT. The basic factorisation is

\[\left[\begin{array}{cc} A & B^{T}\\ B & 0 \end{array}\right] = \left[\begin{array}{cc} A & 0\\ B & S \end{array}\right] \left[\begin{array}{cc} I & A^{-1}B^{T}\\ 0 & I \end{array}\right], \qquad S=-B A^{-1}B^{T}. \]

The preconditioner applies an approximate inverse of this factorisation:

  1. an approximate velocity solve with \(A\) (AMG or ILU);
  2. an approximate Schur solve with \(\widehat S\) (GAMG, HYPRE BoomerAMG, or a pressure Laplacian scaled by the momentum diagonal);
  3. a back-substitution for the pressure coupling.

This is the standard Schur-complement fieldsplit idea. The exact inverse is never formed; the preconditioner only needs a spectrally equivalent approximation. GMRES handles the remaining coupling.

-fieldsplit_pressure_pc_type gamg
-ksp_type fgmres
-ksp_rtol 1e-12

The pressure stabilisation gives a genuine pressure Laplacian, so selfp (use the (1,1) block as the Schur preconditioner) is the natural choice; the older a11 option has the wrong size because the velocity block is 3N and the pressure block is N. For the direct path a single pressure reference row fixes the gauge. For a fully iterative all-Neumann pressure path, create a MatNullSpace with the constant vector and attach it to both the outer matrix and the pressure sub-block. The pressure mean is removed for error norms and reported separately.

The PC needs its own options prefix (PCSetOptionsPrefix(pc, "stokes_")); without it the -fieldsplit_* options are ignored and PETSc silently uses GMRES/bjacobi. The sub-solver choices are exposed as stokes.velocityKsp, stokes.velocityPc, stokes.pressureKsp and stokes.pressurePc.

The current fieldsplit implementation is FGMRES + PC_COMPOSITE_SCHUR, fact_type full, selfp, GMRES + GAMG on the velocity block and preonly + GAMG on the pressure block. The velocity inner tolerance is 1e-10 and the outer tolerance is 1e-12. This keeps memory O(N), avoids local factorisations of the singular Neumann pressure block, and converges in 11–20 outer iterations in 2D and 3–13 in 3D on 1/2/4/8 ranks. It is the schema default; direct remains the validation reference. Fully periodic domains use small diagonal pressure and velocity gauges (1e-6) to remove the two nullspaces; wall-bounded cases keep the pressure reference row and are not perturbed.

5. Navier–Stokes extension

For incompressible Navier–Stokes,

\[\frac{\partial\mathbf{u}}{\partial t} +\nabla\cdot(\mathbf{u}\otimes\mathbf{u}) +\nabla p-\mu\nabla^2\mathbf{u}=\mathbf{f}, \qquad \nabla\cdot\mathbf{u}=0, \]

the same block appears after linearising the convection term. A Picard iteration gives

\[\left[\begin{array}{cc} A+C(\mathbf{u}^{k}) & B^{T}\\ B & 0 \end{array}\right] \left[\begin{array}{cc} \delta\mathbf{u}\\ \delta p \end{array}\right] = -\left[\begin{array}{cc} R_u\\ R_p \end{array}\right], \]

where \(C\) is the linearised convection operator. A Newton iteration adds the velocity-gradient dependence of \(C\). For time-dependent flow, add the mass matrix \(M/\Delta t\) to the velocity block.

The practical path is:

  1. Picard/Newton with the coupled saddle-point solve for steady Navier–Stokes;
  2. semi-implicit time stepping with the same block per step;
  3. SIMPLE/SIMPLEC as an optional segregated path for cases where the coupled solve is too expensive.
