saturnCFD v1 — design

Status: decisions frozen for the substrate; Phase 1 (mesh, configuration, CLI, docs, regression tests) in progress; solver physics starts in Phase 2.

This page is the short version. The binding records are in docs/decisions/; the equations are in docs/theory/; the implementation sequence is in docs/plan/v1-roadmap.md. The folder layout is in docs/plan/repositoryLayout.md and the docs build in docs/plan/documentationPipeline.md.

1. Mission

A single codebase that:

  1. solves scalar transport (Burgers, heat) and incompressible flow (Stokes, Navier–Stokes) on a structured hexahedral mesh imported from Gmsh .msh;
  2. is dimensionally consistent and validated against analytic solutions;
  3. is driven entirely by YAML, with generated templates and strict validation;
  4. is MPI-parallel and performance-portable through Kokkos from the first FVM layer, on CPU and GPU;
  5. remains readable enough that one timestep can be followed from the driver to the last kernel.

2. Accepted architecture

area decision

state collocated cell-centred velocity vector and dynamic pressure
coupling Rhie–Chow face flux; SIMPLE for steady, PISO for transient
parallel MPI Cartesian block decomposition; one owner per cell; 2-layer ghost halo
execution Kokkos CPU/GPU; one rank per GPU; host-staged halo first
linear algebra MPI PETSc Mat/Vec/KSP/PC; no home-grown Krylov

time loop Simulation owns time, step, output, checkpoints and manifest
config typed schema, generated -dumpConfig, strict -checkConfig
units SI only in v1.0; units.system: SI or omitted; non-SI is an error
CLI single-dash camelCase options; -help, -checkMesh, -writeVTK
AMR out of v1.0; revisit after incompressible NS is stable, for two-phase flow

3. Why collocated

Basilisk's default incompressible solver is collocated/centred (with an optional MAC module); Nektar++ and NekRS use collocated nodal points with a lower-order pressure space; OpenFOAM is collocated FV with Rhie–Chow. A staggered MAC grid gives exact discrete continuity and no checkerboard, but it splits the velocity components onto different meshes and fights the vector form, the .msh import and the 2D/3D rule. The checkerboard risk is handled explicitly by Rhie–Chow, and the pressure–velocity coupling is validated before Navier–Stokes.

4. Solver sequence

stage solver main lesson first validation
1 Burgers (scalar, then vector) convection, shocks, limiters, diffusion, time integration viscous traveling wave; inviscid shock
2 heat / convection–diffusion scalar transport, Péclet effects, boundary layers 1D boundary layer; 2D/3D MMS
3 Stokes vector elliptic operator, pressure coupling, PETSc Poiseuille, Couette, cavity at \(Re\to0\)
4 incompressible Navier–Stokes nonlinear convection + pressure projection Ghia cavity \(Re=100/1000\); Taylor–Green

Compressible flow is out of v1.0. Two-phase flow and AMR are later.

4a. Command line and mesh visualisation

saturnCFD case.yaml
saturnCFD -checkMesh mesh.msh
saturnCFD -checkMesh mesh.msh -report results/mesh
saturnCFD -checkMesh mesh.msh -writeVTK results/mesh
saturnCFD -checkConfig case.yaml
saturnCFD -dumpConfig common
saturnCFD -dumpConfig common -writeTemplate common
saturnCFD -help
saturnCFD -help checkMesh
saturnCFD -completion bash

-checkMesh writes <prefix>.vtu and <prefix>.json by default; -writeVTK adds .vtp patches and a .pvd. Open the .pvd in ParaView. The binary is installed with cmake --install buildCPU --prefix "$HOME/.local", so the command is saturnCFD, not ./buildCPU/saturnCFD. -completion prints bash/zsh/fish completion; ctest --preset regression is the short test command. The full option list is in docs/protocols/cli.md.

5a. Dependencies

  • Kokkos — CPU/GPU performance portability.
  • MPI — decomposition and halo exchange.
  • PETSc — MPI linear algebra.
  • yaml-cpp 0.8.x — YAML parsing; no hand-written parser.
  • doctest — test framework.
  • CMake >= 3.24, C++20.

5b. User-editable solvers

A solver is a self-contained directory with its lifecycle, options, state, equations and diagnostics. Users copy a built-in under src/solvers/<name>, add one addSolver(<name>) line to src/solvers/CMakeLists.txt, edit the equations and rebuild. saturnCFDSolver (C++) performs the copy and prints the line. User solvers are compiled into saturnCFD; there is no runtime plugin in v1.0. See guides/writingASolver.md and ADR 0011.

6. What is deliberately not in v1.0

  • unstructured meshes;
  • AMR, regridding, two-phase flow;
  • compressible flow;
  • multi-GPU tuning and GPU-aware halo exchange (the interfaces support them, but the first benchmark is one GPU);
  • non-SI unit systems (v1.0 accepts SI only; other systems are rejected);
  • a home-grown Krylov solver.
